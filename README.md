# Clinic Inventory Management System (CIMS)

Java 21 + Spring Boot + MySQL implementation of the Clinic Inventory Management System mockup.

## Included

- Spring Boot REST API (`@RestController` controllers under `controller/`)
- MySQL persistence with Spring Data JPA
- Flyway schema migration
- Spring Security using database users/roles/permissions and HTTP Basic authentication
- Responsive role permissions (permissions are loaded from the database on authentication)
- Item Master with UoM, reorder-level max 100, reorder-quantity max 500, soft-delete/reactivation and deletion guards
- Global medicine near-expiry threshold
- Locations managed in System Settings (default: Alabang, Cebu, Makati)
- Supplier management with soft-delete safeguards
- Receiving → Pending/Returned/Approved workflow
- Returned receiving line-by-line editing and resubmission
- Optional batch number, required location for every receiving line
- Manual equipment asset tag/serial number; no asset-tag auto generation
- Supervisor approval workflow
- Batch records generated by approved receiving transactions and kept immutable after approval
- FEFO medicine/supply issuance with employee number + employee name
- Editable issuance records with stock reconciliation
- Equipment status-only editing and dedicated disposal workflow
- Transaction log limited to exactly: ADJUSTMENT, DISPOSAL, ISSUANCE, RECEIVING
- Stock Balance / Transaction History / Equipment reports
- Report export to CSV, XLSX and PDF
- Report history containing only generated reports
- Database-backed browser UI based on the HTML mockup in `src/main/resources/static/`

## Browser UI and database persistence

The browser UI at `/` and `/mockup.html` is fully wired to the Spring REST API. Inventory/business data is **not** stored in browser `localStorage`. Create, update, approval, issuance, disposal, user, role, settings, and report operations are sent to `/api/...` and persisted through Spring Data JPA to MySQL.

The browser stores only the current HTTP Basic credential token in `sessionStorage` for the lifetime of that browser tab/session. It contains no inventory records. Opening the application in another browser and signing in reads the same MySQL data. The UI refreshes after mutations, on window focus, and every 10 seconds while it is open.

The top bar also shows a live database status indicator backed by `GET /api/system/health`. If the database connection is lost, the UI shows **Database unavailable** instead of silently falling back to browser storage.

The old localStorage prototype is not included in the runnable project, so there is no alternate browser-local version to accidentally open.

## Requirements

- Java 21
- Maven 3.9+
- MySQL 8.x

Or use Docker + Docker Compose.

## Quick start with Docker

```bash
docker compose up --build
```

Then open:

- Database-backed UI: `http://localhost:8080/`
- REST API: `http://localhost:8080/api/...`

## Run locally

Create the database/user or adjust environment variables:

```bash
export DB_URL='jdbc:mysql://localhost:3306/cims?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Manila'
export DB_USERNAME='cims'
export DB_PASSWORD='cims'
mvn spring-boot:run
```

## Demo accounts

When `SEED_DEMO_DATA=true`, these accounts are created if they do not exist:

| Role | Email | Default password |
|---|---|---|
| Nurse | `nurse@clinic.local` | `ChangeMe123!` |
| Supervisor | `supervisor@clinic.local` | `ChangeMe123!` |
| Administrator | `admin@clinic.local` | `ChangeMe123!` |

Change the password through `DEMO_PASSWORD` for a new database.

### Default permissions

- **Nurse:** Receiving, Issuance, Batches, Equipment, Disposal, Suppliers, Reports, Transaction Log
- **Supervisor:** Receiving Records, Approvals, Batches, Equipment, Reports, Transaction Log
- **Administrator:** Items, Users, Roles, Settings, Locations

Administrator does **not** receive Transaction Log permission by default. If `TRANSACTION_LOG` is granted to the Administrator role, the REST endpoint becomes available to that account after re-authentication.

## Authentication

The API uses HTTP Basic to keep the generated project straightforward and easy to run.

Example:

```bash
curl -u nurse@clinic.local:ChangeMe123! http://localhost:8080/api/session/me
```

## Example: create a receiving request

```bash
curl -u nurse@clinic.local:ChangeMe123! \
  -H 'Content-Type: application/json' \
  -d '{
    "supplierId": 1,
    "referenceNumber": "DR-2026-001",
    "dateReceived": "2026-08-25",
    "remarks": "Routine clinic replenishment",
    "lines": [{
      "itemId": 1,
      "quantity": 100,
      "brand": "MedCore",
      "batchNumber": null,
      "expiryDate": "2027-08-25",
      "locationId": 1
    }]
  }' \
  http://localhost:8080/api/receiving
```

## Example: approve receiving

```bash
curl -u supervisor@clinic.local:ChangeMe123! \
  -X POST http://localhost:8080/api/approvals/1/approve
```

## Reports

Generate JSON preview:

```bash
curl -u nurse@clinic.local:ChangeMe123! \
  -H 'Content-Type: application/json' \
  -d '{"reportType":"TRANSACTION_HISTORY","from":"2026-08-01","to":"2026-08-31","transactionType":"ISSUANCE","itemCategory":"MEDICINE"}' \
  http://localhost:8080/api/reports/generate
```

Export:

```bash
# xlsx can also be csv or pdf
curl -u nurse@clinic.local:ChangeMe123! \
  -H 'Content-Type: application/json' \
  -d '{"reportType":"STOCK_BALANCE","from":"2026-08-01","to":"2026-08-31"}' \
  -o stock-balance.xlsx \
  http://localhost:8080/api/reports/export/xlsx
```

## Frontend startup troubleshooting

Always start `ClinicInventoryApplication` first and open the UI through **http://localhost:8080/**. Do not run `index.html` directly from Eclipse or File Explorer. The frontend is intentionally REST-only and needs the Spring Boot origin in order to reach `/api/**`.

The frontend now includes startup diagnostics and request timeouts. If the JavaScript bundle cannot load, if a saved login cannot be restored, or if MySQL/Spring Boot does not respond, the page shows a concrete error instead of remaining indefinitely on “Connecting to Clinic Inventory Management System…”. The unauthenticated login screen also probes `/api/system/health` to show whether MySQL is reachable.

If Eclipse was already running an older build after replacing project files: stop the application, choose **Project → Clean**, **Maven → Update Project**, restart `ClinicInventoryApplication`, then hard-refresh the browser (`Ctrl+F5`).
